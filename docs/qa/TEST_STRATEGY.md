# Test architecture

## Principle

Core analytical logic must be independently testable from UI, database, and provider APIs. Tests use synthetic or anonymized fixtures only; every discovered parsing or calculation defect becomes a regression fixture/test.

## Unit tests

Sprint 07 retains the parser, normalization, and Data Health suites and adds pure KPI arithmetic/engine tests. Coverage includes fixed-decimal addition/subtraction/multiplication/division/comparison, primitive aggregation, all derived formulas, source breakdowns, reporting-period boundaries, comparison deltas, previous-zero behavior, null versus zero, zero denominators, invalid/incompatible inputs, and the blocked Data Health gate. Independently maintained KPI goldens are compared by tests rather than generated by production code.

## Integration tests

Integration tests exercise synthetic raw CSV -> validation -> parser -> detector -> mapping -> normalizer -> Data Health -> KPI Engine. Sprint 07 cases cover healthy Meta/Google/Shopify, review-required execution, blocked currency refusal, and the critical revenue semantic: Shopify gross revenue feeds commerce Revenue/MER/AOV while same-provider attributed revenue feeds only provider ROAS. `POST /api/normalize/csv` is tested for a compact raw-data-free Data Health + KPI response.

## Connector contract tests

No connector exists yet. The prepared connector contract is: equivalent provider CSV and API reporting data must produce equivalent canonical observation semantics, supported provenance shape, and relevant findings. `fixtures/normalized/` is the CSV-independent golden boundary for that future test suite.

## E2E tests

Playwright verifies source detection, mapping review, successful Meta normalization, Data Health, and a provider-specific KPI scorecard with current/previous/delta facts. Multi-source MER and reconciliation remain below the UI boundary because the intentionally scoped flow accepts one CSV at a time. It has no Change Intelligence, persistence, connector, AI, or report assertions.

## Regression fixtures

Store labelled synthetic/anonymized provider input in `fixtures/raw/`, independent canonical expectation JSON in `fixtures/normalized/`, and manual KPI facts in `fixtures/expected/kpi/`. Never generate expected files from implementation code, use fabricated production evidence, or include client data. `FORMULA_VERIFICATION.md` provides arithmetic reviewers can inspect without reading implementation.

## Tooling and CI expectation

Sprint 03 establishes Vitest for unit/integration tests and Playwright Test for E2E. Expected commands are `npm test`, `npm run test:e2e`, `npm run lint`, `npm run typecheck`, and `npm run build`; all run without external services. Base CI runs locked install, lint, typecheck, unit tests, and build. Playwright remains available locally but outside base CI because browser installation would add disproportionate overhead to the foundation pipeline; it needs no database.
